The Big Picture

  • Software is a set of instructions that tells hardware what to do. It's in phones, cars, appliances, and nearly everything else.
  • The operating system manages hardware and runs applications. Embedded systems make everyday products “smart.”
  • Enterprise software like ERP, CRM, and SCM runs whole organizations. It's powerful, but big rollouts are risky.
  • APIs and web services let systems talk to each other, often by exchanging data formatted as JSON.
  • AI is changing how code gets written. Methods like agile and scrum help teams deliver, and the real cost of software is its total cost of ownership.
Your goals

What You’ll Learn

By the end of this module, you should be able to:

  • Tell hardware from software, and name the major categories of software.
  • Explain what an operating system does, and define firmware and embedded systems.
  • Compare desktop and enterprise software, and describe ERP, CRM, SCM, BI, and DBMS.
  • Explain client-server computing, web services, and APIs, and why data standards like JSON matter.
  • Describe how software is written, including compiled vs. interpreted code, AI coding tools, and low code/no code.
  • Compare waterfall and agile development, and explain scrum.
  • List the parts of total cost of ownership and the common reasons tech projects fail.
Sections 9.1–9.2

Hardware, Operating Systems & Apps

Hardware is the physical stuff: chips, screens, keyboards, and storage. Software is the set of instructions that tells the hardware what to do. Think of it as layers:

Key idea

Operating system (OS)

Controls the hardware, provides the user interface, and sets the standards apps must follow. That makes it a platform.

Key idea

Firmware

Software stored on chips inside a device, like the BIOS that starts up a PC. It can often be updated.

Key idea

Embedded systems

Special-purpose software inside products like cars, thermostats, and TVs that makes them “smart” and lets them report problems.

Section 9.3

Application Software: Desktop vs. Enterprise

Desktop software (like a word processor) usually serves one user. Enterprise software serves many users across an organization. Many firms buy a software package from a vendor like SAP, Oracle, Salesforce, or Microsoft instead of building their own.

The big enterprise systems
SystemWhat it does
ERP (enterprise resource planning)Integrates accounting, finance, inventory, HR, and more into one system and one database
CRM (customer relationship management)Supports sales, marketing, and customer service
SCM (supply chain management)Manages the flow from raw materials to delivered products
BI (business intelligence)Uses data from other systems for reporting and analysis
DBMS (database management system)Creates, stores, and manages the data all of these systems depend on
Watch out · Packaged systems: rewards and risks

Packaged software spreads “best practices” and lets departments share data. But rollouts can be expensive, take years, and force a firm to change how it works. If the system doesn't fit the business, the results can be disastrous. Hershey's ERP problems famously disrupted its Halloween candy shipments.

Section 9.4

Distributed Computing, Web Services & APIs

In distributed computing, systems in different places work together. The most common setup is client-server: a client (like your browser or phone app) makes requests, and a server program answers them.

APIs (application programming interfaces) and web services let one program ask another to do something, like "check this payment," "get this weather forecast," or "show this map." That's how a ride-sharing app uses Google Maps or a store's checkout uses Stripe.

What API data looks like · JSON

Most APIs send data as JSON (JavaScript Object Notation): labeled values in a format both people and programs can read.

{
  "city": "Raleigh",
  "tempF": 72,
  "conditions": "Sunny"
}

Older systems often use XML or EDI standards. Agreeing on a format is what lets machines from different companies understand each other.

Why it matters

APIs turn products into platforms. When outside developers can build on your service, you get complementary benefits and network effects (remember Module 7).

Section 9.5

Writing Software (Now with an AI Co-Pilot)

Developers write code in a programming language using an IDE (a programmer's word processor, debugger, and more). Then that code has to become something a computer can run:

Compiled

Translated ahead of time

Code is compiled into machine instructions for a specific processor and OS. It runs fast, but each platform needs its own version.

Interpreted

Translated as it runs

Scripting languages like JavaScript and Python are interpreted line by line. They're flexible and quick to write.

Java

“Write once, run anywhere”

Java was designed to run on any device that has a Java virtual machine.

AI is changing programming

Large language model tools can suggest, explain, and write code. They're not the “death of programming.” Instead, more people will write code, and developers will spend more time designing, reviewing, and testing. AI-written code can still contain bugs and security holes.

Key concept · Low code / no code (LCNC)

Visual, drag-and-drop tools let non-programmers build simple apps and workflows. They're great for quick fixes, but apps built without IT's knowledge can create security, quality, and maintenance problems.

Section 9.6

Waterfall vs. Agile (and a Sprint through Scrum)

The software development lifecycle (SDLC) moves through planning, analysis, design, building, testing, deployment, and maintenance. Teams organize these steps in different ways:

Two development methodologies
WaterfallAgile
ApproachDo each step fully, in order, one timeBuild in small pieces and improve continuously
StrengthsClear requirements and a blueprint up frontFrequent releases and fast reaction to feedback
WeaknessesSlow. Hard to change course. Problems surface late.Less up-front predictability. Needs disciplined teams.

Scrum in a nutshell

  1. Product backlogA prioritized wish list of features, owned by the product owner.
  2. SprintA small team (fewer than 10 people) builds a chunk of work in a short cycle, usually one to six weeks.
  3. Daily stand-upA quick check-in: what I did, what I'll do, and what's blocking me. A scrum master removes obstacles.
  4. Review & retrospectiveShow what was built, gather feedback, improve the process, and start the next sprint.
Watch out · Feature creep

Adding “just one more feature” again and again expands a project's scope, delays it, and raises costs.

Sections 9.7–9.8

Beyond the Price Tag: TCO and Tech Failure

The purchase price is just the start. Total cost of ownership (TCO) includes:

Cost

Buying & building

Software licenses, hardware, development, and integration with other systems.

Cost

People

Training, support staff, and consultants.

Cost

Keeping it running

Maintenance, upgrades, security, and compliance with laws and regulations.

Projects fail for familiar reasons: unclear goals, weak leadership support, unrealistic deadlines, poor testing, and ignoring users. Frameworks like CMMI help firms judge how mature their development processes are.

Case · HealthCare.gov

The U.S. health insurance website crashed at launch in 2013. Many contractors had little coordination, there was too little end-to-end testing, and no one had clear authority. A small “tech surge” team using modern, agile practices stabilized the site within weeks.

Case · Volkswagen's software struggles

VW made great cars but struggled to become a software company. Its early electric vehicles, like the ID.4, had buggy, slow software, and its in-house software unit fell behind schedule. Adding code to a product doesn't make a firm a digital enterprise. That takes new skills, culture, and processes.

Vocabulary

Key Terms

Want every term from every module in one place? Try the searchable glossary.

Hardware
The physical parts of a computing system: processors, memory, storage, screens, keyboards, and so on.
Software
A program or set of programs: precise instructions that tell hardware what to do.
Operating system
Software that controls the hardware and sets the standards that apps use to run.
User interface (UI)
How people interact with a device, such as windows, buttons, menus, and touch gestures.
Firmware
Software stored on nonvolatile chips inside a device. It can often be updated.
Embedded system
Special-purpose software built into a physical product to make it smarter.
Enterprise software
Applications that serve many users across an organization.
ERP
Enterprise resource planning: a software package that ties together a firm's major functions, like accounting, HR, and inventory.
CRM
Customer relationship management: systems that support sales, marketing, and customer service.
SCM
Supply chain management: systems that manage the flow of materials and products from suppliers to customers.
Business intelligence (BI)
Systems that use data from other systems for reporting and analysis.
DBMS
Database management system: software for creating, maintaining, and using data.
Client-server
A setup where client programs make requests and server programs fulfill them.
Web services
Small pieces of code that let machines interact over a network.
JSON
JavaScript Object Notation: a popular, readable format for sending data between programs.
Compile
To convert human-written code into machine instructions a processor can run.
Scripting language
A language that's interpreted line by line as it runs, like JavaScript or Python.
Low code/no code
Visual tools that let people build apps with little or no programming.
SDLC
Software development lifecycle: the stages of planning, building, testing, and maintaining a system.
Waterfall
A step-by-step development method that completes each phase in order.
Agile
A development approach that delivers work in small, frequent pieces and improves continuously.
Scrum
An agile framework where small teams deliver work in short sprints with defined roles.
Feature creep
When a project's scope keeps expanding with new features.
Total cost of ownership (TCO)
The full cost of a system, including purchase, training, support, maintenance, and upgrades.
